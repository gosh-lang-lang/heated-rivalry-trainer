# Heated Rivalry — тренажёр английских слов

Бриф для переноса проекта в Claude Code. Положи этот файл в корень репозитория (можно переименовать в `CLAUDE.md`, чтобы Claude Code читал его автоматически), рядом — `index.html` (текущий прототип) и `words.json` (слова).

---

## 0. Идея

**Пользователь:** Евгений, русскоязычный, английский B1–B2. Хорошо понимает на слух, мало практики говорения, не хватает словарного запаса. Устройства: iPhone, iPad, MacBook.

**Задача:** читать в оригинале роман *Heated Rivalry* (Rachel Reid) и параллельно расширять словарный запас так, чтобы слова переходили в активную речь, а не просто «узнавались при чтении».

**Как это работает сейчас вручную:**
1. Читает страницу, подписывает перевод над незнакомыми словами.
2. Выписывает слова с переводом в бумажный блокнот (≈25–30 слов на страницу в начале книги).
3. Фотографирует страницы и блокнот → Claude проверяет переводы по контексту и добавляет слова в тренажёр.
4. Занимается в тренажёре, перечитывает страницы.

**Принципы обучения (не терять при переписывании):**
- **Маленькие порции:** новые слова блоками по 5–6.
- **Лестница сложности для каждого слова:** знакомство → узнавание (выбор) → вспоминание (вписать самому) → контекст (пропуск в предложении) → применение (собрать фразу).
- **Интервальное повторение:** у каждого слова уровень и дата следующего показа.
- **Два занятия в день по ~15 минут:** утром учим, вечером закрепляем и применяем.
- **Применение в жизни:** свои предложения о своей жизни с проверкой ИИ, плюс произнесение вслух.
- **Связь с книгой:** шаг «перечитай страницы» с отметкой.
- **Ошибки внутри занятия** возвращаются в конец (как в Duolingo); счёт считается по первой попытке.
- **Все слова активные:** цель — использовать в речи. Редкие книжные слова просто повторяются реже.
- **Метрики:** счёт каждого занятия, сравнение с прошлым разом, серия дней, слова с частыми ошибками.

## 1. Текущее состояние (прототип v2)

`index.html` — один самодостаточный файл (HTML + CSS + JS, без сборки), опубликованный как артефакт Claude. Использует возможности платформы Claude через `claude.use(...)`:

| Возможность | Для чего | Что взять вместо в своей версии |
|---|---|---|
| `db` | хранит состояние в документе `state/main` | свой бэкенд (например, Supabase) + авторизация |
| `sample` | проверка своих предложений моделью Claude | Anthropic API через серверную функцию (ключ только на сервере) |
| `tts` | озвучка голосом Claude (нет в Safari и мобильных приложениях) | TTS-API или Web Speech API (`speechSynthesis`) |
| `dictation` | распознавание речи (только Chromium и десктопное приложение Claude) | Web Speech API / Whisper; на iOS — диктовка с клавиатуры |

Без этих возможностей страница всё равно работает: состояние лежит в `localStorage` (ключ `hr2_state`), озвучка идёт через `speechSynthesis`, вместо кнопки микрофона — текстовое поле.

**Экраны:**
- **Главная:** серия дней, карточки «Утро · учим» и «Вечер · применяем», распределение слов по уровням, настройка «новых слов за утро» (6/12/18/24).
- **Занятие:** прогресс-бар, задание, нижняя панель «Проверить / Дальше» с цветной обратной связью.
- **Словарь:** все слова по партиям, уровень, дата следующего повторения, заметка и пример.
- **Статистика:** 14 дней (утро/вечер в %), частые ошибки, история своих предложений с исправлениями.
- **Итог занятия:** %, сравнение с прошлым разом, новые слова, минуты, серия.

**Картинки:** сейчас эмодзи (артефакт не может грузить внешние изображения).

## 2. Модель данных

### Слова (`words.json`)
```jsonc
{
  "version": 1,
  "batches": [{ "id": 1, "title": "Отзывы критиков", "pages": "отзывы критиков (стр. 1)" }],
  "words": [{
    "id": "sacred",                 // slug от en
    "batch": 1,
    "picture": "🙏",
    "en": "sacred", "ipa": "/ˈseɪkrɪd/", "ru": "священный",
    "note": "…",                    // пояснение / поправка
    "example": "For him, Sunday morning is sacred.",
    "exampleRu": "Для него утро воскресенья — святое.",
    "blank": "sacred",              // точный фрагмент example, который прячется в задании «впиши»
    "correctionOfMyTranslation": true  // перевод в блокноте был неточным
  }],
  "sentences": [{ "en": "…", "ru": "…", "words": ["devour", "entire", "novel"] }]  // банк фраз для сборки
}
```

### Состояние пользователя (`state/main`, тот же формат в `localStorage` → `hr2_state`)
```jsonc
{
  "upd": 1763650000000,                       // ms, для слияния «кто новее»
  "settings": { "newPerDay": 12 },
  "srs": { "<wordId>": { "lvl": 0-6, "due": "YYYY-MM-DD", "intro": "YYYY-MM-DD", "right": 0, "wrong": 0 } },
  "days": { "YYYY-MM-DD": {
      "morning": { "score": 34, "total": 38, "mins": 14, "newN": 12, "at": "ISO" },
      "evening": { … }, "extra": [ … ], "reread": true } },
  "sent": [{ "at": "ISO", "words": ["endure"], "text": "…", "ok": false, "corrected": "…", "comment": "…", "pending": false }]
}
```

### Интервальное повторение
- Интервалы по уровню: `[0, 1, 3, 7, 14, 30, 60]` дней.
- Знакомство со словом: `lvl=1`, `due=завтра`, `intro=сегодня`.
- Повторение, первая попытка верна: `lvl=min(lvl+1,6)`, `due=сегодня+IV[lvl]`.
- Ошибка: `lvl=1`, `due=завтра`.
- Вечерняя проверка, ошибка: `lvl=1`, `due=завтра`.
- Группы для UI: новые (0), учу (1–2), знакомо (3–4), выучено (5–6).

### Состав занятий
- **Утро:** до 20 слов на повторение (`lvl<3` — выбор перевода или аудирование, `lvl≥3` — вписать), затем новые блоками по 6: `intro` ×6 → `pick` ×6 → `pairs` → `listen` ×3 → `type` с подсказкой ×6 → `build` ×3 (из банка фраз, где все слова уже известны, иначе из примеров).
- **Вечер:** `type` без подсказок по утренним словам (до 12) → `write` ×3 (своё предложение, 1–2 слова, проверка ИИ) → `speak` ×2 (своё исправленное предложение, порог 80% слов) → `reread`.
- **«Ещё 6 новых»** после утра — только блок новых слов.
- Ответ в `type` сравнивается после нормализации; для слов длиннее 5 букв принимается одна опечатка (расстояние Левенштейна = 1).

### Промпт проверки своего предложения (сейчас)
Модели передаются целевые слова и текст ученика. Она возвращает JSON: `{"ok": bool, "corrected": "...", "comment": "1–2 предложения на русском"}`. `ok=true` — только если нет ошибок и целевое слово употреблено верно.

## 3. План

### Фаза 0 — догфудинг (сейчас, 1–2 недели)
- Ежедневно заниматься в текущем артефакте, копить данные.
- Вести `FEEDBACK.md`: что раздражает, где бросил занятие, чего не хватает.
- **Готово, когда:** есть 10+ дней данных и список болей.

### Фаза 1 — каркас и перенос
- Стек (рекомендация): Vite + React + TypeScript, `vite-plugin-pwa`, деплой на Vercel или Netlify.
- Вынести слова в `words.json`, логику SRS и сборку занятий — в чистые модули с юнит-тестами (без DOM).
- Перенести все экраны и типы заданий 1:1.
- Импорт состояния из JSON-экспорта прототипа (схема выше).
- **Готово, когда:** новая версия проходит утро и вечер так же, как прототип, импорт сохраняет уровни и серию, тесты SRS зелёные.

### Фаза 2 — синхронизация и аккаунт
- Supabase (Postgres + Auth): таблицы `words`, `word_state`, `sessions`, `sentences` или один JSON-документ на пользователя, как сейчас.
- Офлайн-режим: локальная копия + слияние по `upd` или по записям.
- **Готово, когда:** прогресс одинаковый на iPhone, iPad и Mac, работает без сети.

### Фаза 3 — ИИ на своём бэкенде
- Серверная функция → Anthropic API для проверки своих предложений (ключ никогда не попадает в клиент).
- Добавление партии: фото страниц и блокнота → Claude (vision) распознаёт слова, проверяет переводы по контексту, генерирует пример, IPA, пояснение и картинку-подсказку → экран ревью → запись в `words.json` / БД.
- **Готово, когда:** новую партию можно добавить без чата, за пару минут.

### Фаза 4 — «красиво» и удобно
- Push-напоминания утром и вечером (Web Push работает на iOS 16.4+, если PWA установлено на экран «Домой»).
- Настоящий голос (TTS-API) с кэшированием аудио; распознавание речи с оценкой произношения.
- Иллюстрации вместо эмодзи (единый стиль), анимации прогресса, звук на верный ответ.
- **Готово, когда:** приложение установлено на всех трёх устройствах и напоминания приходят.

### Фаза 5 — аналитика продукта
- Метрики: доля завершённых занятий, точность по типам заданий, время на задание, удержание слов (верно через 7/30 дней), прочитано страниц.
- Еженедельный отчёт → решения о доработках.

### Опционально — нативное приложение (SwiftUI)
Если упрёмся в ограничения PWA: iCloud-синхронизация, виджеты, уведомления. Для постоянной установки на свои устройства нужен Apple Developer Program ($99 в год).

## 6. Статус (2026-11-20)
**Фаза 1 — каркас готов.** `app/`: `npm install`, `npm run dev`, `npm test`, `npm run build`.
- `app/src/core/` — чистая логика без DOM: `srs.ts` (интервалы, уровни, серия), `plans.ts` (состав утра и вечера), `session.ts` (оценка по первой попытке, возврат ошибок в конец, итог), `text.ts` (нормализация, Левенштейн, говорение), `state.ts` (импорт и экспорт, слияние по `upd`), `check.ts` (промпт и разбор ответа ИИ). 52 юнит-теста.
- `app/src/screens/` — главная, занятие (все 9 типов шагов), словарь, статистика, итог: перенесены 1:1 со стилями прототипа.
- Состояние: `localStorage` → `hr2_state`, формат прототипа. Импорт: вставить JSON или выбрать файл.
- Озвучка: нейросеть **Kokoro** на своём сервере (`app/server/`, `npm run server`, порт 8787; в dev Vite проксирует `/api`). `POST /api/tts {text, voice}` → `{url}` → MP3 из кэша `server/cache/tts/`; новая фраза генерируется ~1 с в отдельном потоке, из кэша отдаётся за миллисекунды. При старте сервер прогревает всю колоду голосом по умолчанию (`af_heart`). Голос выбирается на главной, отдельно на каждом устройстве. Если сервер недоступен — лучший системный голос (`core/voices.ts` отсекает шуточные голоса macOS, понимает локализованные имена). Офлайн-озвучка не нужна (решение пользователя).
- Продакшен: `npm run build && npm start` — тот же сервер раздаёт `dist/` и `/api`. Нужен хостинг с постоянным диском под кэш и ~1 ГБ памяти (модель fp32 ~330 МБ; `TTS_DTYPE=q8` — ~90 МБ). Serverless (Vercel/Netlify) не подходит.
- Микрофон: `SpeechRecognition`/`webkitSpeechRecognition`, иначе текстовое поле.
- **Регрессия — Playwright** (`app/e2e/`, `npm run e2e`, `npm run e2e:ui`): проекты `desktop-chrome` и `iphone` (WebKit). Время зафиксировано (2026-11-20 09:00 МСК), `Math.random` детерминирован, `/api/tts` замокан — Kokoro для тестов не нужен. `e2e/helpers.ts → playSession()` проходит любое занятие по данным `words.json`. Тесты опираются на тексты кнопок, роли, aria-label, id `chk`/`next` и `data-say` у кнопки озвучки — при редизайне их сохранять.
- Git: репозиторий в корне, ветка `main`, приватный GitHub `gosh-lang-lang/heated-rivalry-trainer`.
- **Прод (VPS 195.133.197.130):** Docker-контейнер `heated-rivalry` рядом с проектами spillthetea и motivator, общий Caddy, домен `heated-rivalry-trainer.spill-the-tea.xyz`. **Сайт закрыт — на любой запрос 500, пока нет авторизации.** Как обновлять, открывать и откатывать — `deploy/README.md`.
