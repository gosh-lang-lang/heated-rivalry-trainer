- **День урока решает сервер, а не часы устройства (2026-11-21, решение пользователя):** раньше «сегодня» было `new Date()` устройства — перевёл часы на четверг, и урок записан в четверг: серию можно было накрутить, даты повтора сдвигались, поездка в другой пояс двигала «сегодня». Теперь (`core/serverday.ts`, `server/progress.ts`):
  - **Сервер ставит метку и выбирает день.** На каждый итог части урока, которого у него ещё не было, сервер ставит `srv` (UTC ms): `at` устройства, если оно не в будущем и не старше 48 часов по часам сервера (занимались без сети — честное занятие не теряется), иначе — время получения (`trustedTime`). День — `srv` в поясе пользователя (`Intl`, переходы на летнее время — сами). Часть 1 и «ещё 6 новых» — в день `srv`; часть 2 — в день своего урока, если он не позже дня `srv` и не раньше его на `CARRY_DAYS` (перенос), иначе в день `srv`; `srv` части 2 не раньше `srv` её части 1. Выбран вариант «сервер перекладывает ключи `days`», а не журнал событий: модель данных почти та же, экраны не менялись, всё по-прежнему выводится из `days`.
  - **Подтверждённое не переделать.** Итог узнаётся по «имени» — вид занятия + `at`. Что уже лежит на сервере, сервер берёт из своей копии: прислать его под другим днём или с другой `srv` нельзя; присланные `srv`, `tz`, `tzAt` и более новый `reset` не принимаются.
  - **Слияние и несколько устройств** (`mergeStates`): одно и то же занятие под разными днями остаётся одно — подтверждённое сервером, там, куда его положил сервер (устройство, чьи часы врали, после синхронизации держит его в серверном дне, без двойника); в одном месте дня подтверждённое побеждает неподтверждённое, оба подтверждены — позднее по `srv`; опустевший день пропадает. Пока у устройства есть неподтверждённые итоги, синхронизация начинается с отправки (`lib/sync.ts`): сервер раскладывает их раньше, чем устройство сливает его копию. Порядок слияния по-прежнему не важен, повтор ничего не меняет; `reset`, `runAt` и настройки по пунктам работают как раньше.
  - **«Сегодня» на устройстве — серверное.** Каждый ответ `/api/state` несёт часы сервера `now`; приложение считает «сейчас» как часы устройства плюс поправка (`setClock`, `clockNow`, `nowDate` в `core/dates.ts`), день — в поясе `state.tz` (пока его нет — в поясе устройства). Поэтому и день в ключе, и даты повтора (`srs.due`, `intro`) приложение считает уже от серверного дня. Без сети поправка — последняя известная за сеанс; если часы перевели без сети, сервер переложит итог при синхронизации. Приветствие и «часть 2 лучше после 18:30» — по-прежнему местное время устройства.
  - **Даты повтора остались на устройстве**, сервер их проверяет (`clampWords`): у слов, изменённых присланной копией, знакомство не позже сегодня сервера, повтор не позже сегодня + интервал уровня (редкое — по `words.json`); слово, знакомившееся в части, которую сервер переложил в другой день, переезжает вместе с ней (повтор сдвигается так же). Раньше — можно: это только приближает повторение. Перенести SRS на сервер целиком значило бы хранить журнал ответов — не нужно.

### 1. Текущее состояние (прототип v2)

`index.html` — один самодостаточный файл (HTML + CSS + JS, без сборки), опубликованный как артефакт Claude. Использует возможности платформы Claude через `claude.use(...)`:

| Возможность | Для чего | Что взять вместо в своей версии |
|---|---|---|
| `db` | хранит состояние в документе `state/main` | свой бэкенд (например, Supabase) + авторизация |
| `sample` | проверка своих предложений моделью Claude | Anthropic API через серверную функцию (ключ только на сервере) |
| `tts` | озвучка голосом Claude (нет в Safari и мобильных приложениях) | TTS-API или Web Speech API (`speechSynthesis`) |
| `dictation` | распознавание речи (только Chromium и десктопное приложение Claude) | Web Speech API / Whisper; на iOS — диктовка с клавиатуры |

Без этих возможностей страница всё равно работает: состояние лежит в `localStorage` (ключ `hr2_state`), озвучка идёт через `speechSynthesis`, вместо кнопки микрофона — текстовое поле.

**Экраны:**
- **Главная:** серия дней, карточки «Утро · учим» и «Вечер · применяем» (в новой версии — «Урок N · часть 1 — учим» и «часть 2 — применяем»), распределение слов по уровням, настройка «новых слов за утро» (6/12/18/24).
- **Занятие:** прогресс-бар, задание, нижняя панель «Проверить / Дальше» с цветной обратной связью.
- **Словарь:** все слова по партиям, уровень, дата следующего повторения, заметка и пример.
- **Статистика:** 14 дней (утро/вечер в %), частые ошибки, история своих предложений с исправлениями.
- **Итог занятия:** %, сравнение с прошлым разом, новые слова, минуты, серия.
